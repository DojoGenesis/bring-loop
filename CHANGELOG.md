# Changelog — bring-loop

## 2026-10-02 — bring-loop v0.1.2 — hooks run under python3

Both hook commands (SessionStart brief, Stop nudge) called bare `python`, which recent macOS doesn't
ship (only `python3`), so neither hook ran there. They now call `python3 "${CLAUDE_PLUGIN_ROOT}/hooks/<file>.py"`.
The same change covers every other place that told a user or the agent to run bare `python`: the
bring and bring-setup skills, the usage strings in `bring_core.py` (including the brief injected at
session start), the README quick start and `llms.txt`.

A regression test (`tests/test_hooks_interpreter.py`) parses `plugin/hooks/hooks.json` and fails on any
command that isn't exactly that `python3` form, runs both hooks with `python` absent from PATH, and
sweeps the repo's text files for bare-`python` invocations. No logic changed.

If `check` reports DRIFT right after you update, run `scoreboard` once: the generated header now
names `python3`.

The brief injected at session start now gives the `log` command with the absolute path of
`bring_core.py` (hooks run from the project root, where a relative path doesn't resolve). The `bring`
and `bring-setup` skill descriptions are trimmed to 250 characters or fewer, and the regression test
now also sweeps shell, YAML and TOML files and list-form launches of a bare interpreter.

Plugin version bumped 0.1.1 → 0.1.2 so the version-keyed plugin cache re-copies the fix.

## 2026-10-02 — bring-loop v0.1.1 — generated queues stop hiding open multi-step items

`open_actions` used to drop any id that had ever logged `sent` or `decided`. When `actions.md` is
regenerated from an upstream source of truth, multi-step items legitimately log `sent` while still
open, so they vanished for good. Now `closed` and `shipped` hide an id permanently; on a generated
`actions.md` (`generated_utc:` frontmatter or a `GENERATED by` header) `sent` and `decided` hide it
only until the next regeneration. Hand-written files keep the old rule.
